# Upgrading to 0.2

This page lists what a C++ application must change when moving from carta-zarr
0.1 to 0.2. How the library chooses reading rules is described in
[schema versions and reading rules](../reference/schema-versions.md); the full
list of changes is in the [changelog](../changelog.md).

## Rebuild against 0.2

Use `find_package(CartaZarr 0.2 CONFIG REQUIRED)`, then rebuild and relink your
application. Before 1.0, minor versions may change the ABI: a 0.1 binary is not
compatible with 0.2.

## What to check in your application

| Change in 0.2 | What to do |
|---|---|
| `ObservationInfo::date_obs` is removed; a string observation date is no longer read | Use `mjd_obs` and `timesys` |
| `DatasetDescriptor::schema_version` and `SchemaProbeResult::schema_version` report what the store declares, or empty, rather than `1.2` for every store | Do not compare it to `1.2`; inspect diagnostics to tell which rules were used |
| New `DiagnosticCode::unversioned_schema` and `unsupported_schema_version`, and `ErrorCode::unsupported_schema_version` is now emitted | Handle them where you switch on codes; print unknown codes with `DiagnosticCodeName` |
| A geocentric spectral frame is reported as `GEO` rather than `GCRS` | Update any comparison against frame names; `GEO` is the name casacore accepts |
| A `sky`-typed image named by a non-base data group reports that group's name (`model`, `residual`, `dirty`) as its `image_role`, rather than `sky` | Choose images by the reported role or ID, not by assuming every sky-typed image is `sky` |
| XRADIO's image names, including `SKY_MODEL`, `SKY_RESIDUAL` and `SKY_DIRTY`, are listed first | A dataset without `SKY` may default to one of them instead of its point spread function |
| An image's role is no longer read from `image_type`, and a numeric equinox is no longer read | Re-convert such datasets with XRADIO |
| `ReadOptions::read_budget_bytes` bounds what a read holds, not what it decodes: a chunk costs about three times its decoded size | Leave it at zero for the default, or roughly triple a budget you set for 0.1 to keep the same number of chunks in flight |
| New `ImageDescriptor::sub_type`, and a single-channel 0.0.2 image takes its increment from `channel_width` | Optional: use `sub_type` for the image type (`Intensity`, `SpectralIndex`, …) instead of assuming intensity |

The [quickstart](../quickstart.md) prints the declared version and dataset
diagnostics before selecting an image. Its opened descriptor also shows the
subtype and available spectral frame/increment.
